## Mapping DW classes and fields to bitwerk model concepts

Pin order is the order of `TDevice.pins` (a TGraphicList whose children are TPin objects). It was found from pin geometry and confirmed against IC macros with datasheet pin numbers (74HC74, 74HC76, 74HC125). `kind`: 0 = tag/none, 1 = input, 2 = output, 3 = tri-state output or bidirectional.

| DW class / field | bitwerk concept | notes |
|---|---|---|
| `T{2,3,4}{And,Nand,Or,Nor}Gate`, `T2XorGate`, `T2XnorGate` | gate AND/NAND/OR/NOR/XOR/XNOR | Input count is encoded only in the class name. DW has no 5–8-input gates and no 3/4-input XOR/XNOR (the Parts Centre has 5AND/5NAND/6NAND… as macros). Pins: `[OUT, IN_n … IN_1]`; inputs run bottom-to-top (y+10 first). The inputs are commutative, so order only matters for geometry. |
| `TNotGate` | NOT | pins `[OUT, IN]` |
| `TTriState` | tri-state buffer | pins `[IN, OUT(kind 3), EN]`; EN is active high (74HC125 puts a NOT in front of /OE). |
| `TDFlipFlop` | D FF, rising edge, master-slave | pins `[Q, /Q, D, CLK, CLR, PRE]`; CLR and PRE are active high and asynchronous. No stored trigger option: the edge is fixed by the class. |
| `TJKFlipFlop` | JK FF, falling edge, master-slave | pins `[Q, /Q, J, CLK, CLR, PRE, K]` |
| `TRSFlipFlop` | RS latch (level) | pins `[Q, /Q, S?, R?]` (top and bottom left). S/R order is inferred from symbol convention and **not verified**. Has no clock, PRE or CLR. |
| — | latch / FF with configurable edge | DW stores no trigger/edge field. bitwerk's latch and edge options have no source data. |
| `TMemoryDevice` | RAM/ROM | `is_ram` (True = RAM; ROM has no R/W pin), `address_bits` (4–14 seen: 8, 9, 14), `data_bits` (4, 8, 16 seen), `contents` = 2^address_bits words (u16 each). Pins: `[A(n-1)…A0, D(m-1)…D0 (kind 3), CS, R/W (RAM only)]`. CS is active low. R/W: low = write. MSB pin first is inferred from the "A7"/"D7" labels at the top. Always `has_graphics`. |
| `TInteractiveInput` | Switch / input (toggle) | `state` 0 or 65535 (= high); `pulse` (probable "Pulse Input"); pins `[OUT]` |
| `TInteractiveSwitch` | **gap**: a two-terminal switch (bidirectional contact) | pins `[T1(kind 3), T2(kind 3)]`; `switch_type` (0 = toggle, probably 1/2 = push-to-make/break); `flag_3c` unknown (state?). bitwerk "Switch" is probably an input source, which is a different concept. |
| `TClockDevice` | Clock | `sequence` "01" (or "10" = phase); `color` = LED colour. **Frequency is global** (Circuit → Clock Speed menu, kept in the Windows registry), not in the file. |
| `TBitGenerator` | **gap**: sequence generator | `sequence` = string of '0'/'1' (up to 64 bits, cyclic); `color` |
| `TSupply` / `TGround` | **gap**: constant 1 / constant 0 | pins `[OUT]`. Could map to a constant-source component. |
| `TLEDDevice` | LED | `color` = TColor (0x00BBGGRR): 255 red, 65280 lime, 65535 yellow, 32768 green. Pins `[IN]`. |
| `TLEDSegmentDevice` | **gap**: 7-segment display | pins `[a,b,c,d,e,f,g]` left-to-right (verified by the Counter sample decoding 01..14). `common_cathode` True = segments active high; False = active low. The field exists only in v30/v34; in v20 assume active high. |
| `TNumericDevice` | **gap**: numeric output | `input_lines` (4/8), `color`; `unk_58` (17–26, probably font size), `unk_5c` (always 0, probably display format), `unk_color_60` (grey, probably the leading-zero dim colour), `flag_64` unknown. |
| `TTextDevice.name_label` / `text_pos` | **gap**: device name label | A TGraphicText name shown in the Logic History; `text_pos` 0..3 = left/right/top/bottom. |
| `THistoryDevice.logic_history` | **gap**: logic-history (waveform) membership | |
| `TMacro` | macro (sub-circuit) | `devices` / `tags` / `inputs` / `outputs` / `solders` / `wires` lists; `pins` = external TMacroPins in DIL order (1-based index = template pin number); `children` = icon/template drawing; `datasheet` (relative PDF path). The macro **name** is only in the file header (prop 100 or the v30 info string) for the root. Nested macros carry no name, only their drawing (which usually contains the part number as text) and the datasheet path. Nested macros are **embedded copies**: 2762 instances in the corpus, 195 unique implementations. |
| `TTagDevice` | macro tag pin | `macro_pin` → the inner TMacroPin; `.partner` → the outer TMacroPin on the macro's `pins` list. The tag's own TPin (kind 0) is the inner net. `direction` 1 = in, 2 = out, 3 = tri/bidir. The tag text is the DIL pin number. |
| `.dwt` template | DIL template | graphics list + TGraphicList of TMacroPins (no associations). 8/14/16/18/20/24/28-pin DIL and a Relay. |
| `TWire` | orthogonal wire segments | `points` = polyline (99.2 % of segments are axis-parallel; diagonal segments occur and need to be split or kept). `end1` ↔ first point, `end2` ↔ last point; an end is a TPin, TMacroPin or TSolder. The end point equals the pin-outline centre. |
| `TSolder` | junction | Always exactly 3 wires. A 4-way node = 2 solders. Position x,y. |
| `TWire.pen_color` | **gap**: wire colour | Only 0 (black) or 0xC0C0C0 (silver). Meaning unclear; probably cosmetic or legacy. |
| `TGraphicText` | **gap**: text annotation | text, font size (pt), colour, bold (weight 700), `angle` (0/90/180/270/360), `overbar` (a TPolyline), `flag_8d` (probably italic), `flag_94` unknown |
| `TPolygon` / `TPolyline` (in macro `children` or device graphics) | **gap**: free graphics | macro icon drawing, overbars, rotated-device bodies |
| `has_graphics` = True on a gate/tri-state | rotated gate | Rotation is **not stored as an angle**. A rotated device stores its own drawing and pin outlines in absolute coordinates and **no x,y**. The importer must derive the centre (bbox) and the rotation from the output pin's position relative to the inputs (multiples of the Grid Setup "Rotation Angle", usually 90°). |

### Gaps in bitwerk (DW features with no bitwerk counterpart)

- Sequence generator (`TBitGenerator`), constant Vcc/Ground (`TSupply`/`TGround`), two-terminal bidirectional switch (`TInteractiveSwitch`), 7-segment display, numeric output.
- Free text annotations with rotation, overbar, colour and size; free polygons/polylines; macro icon drawings.
- Device name labels and logic-history membership; LED and clock colours.
- Rotated devices are drawn with arbitrary geometry. Non-90° angles are possible in principle (the rotation step is configurable).
- Embedded datasheet path per macro; header description.
- Clock frequency is not in the file (bitwerk needs a default, e.g. 1 Hz, or must ask the user).

### bitwerk features with no DW source

- 5–8-input gates (DW uses macros); 3/4-input XOR/XNOR; selectable FF edge or latch mode (fixed per class in DW); 1/2-bit data width for memory (only 4/8/16 seen, though the dialog may allow 1/2).
